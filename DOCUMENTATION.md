# Reddit Clone: Complete Project Documentation

This document serves as the comprehensive technical guide for the Reddit Clone project.

## 1. Project Overview

The **Social Media Platform (Reddit Clone)** is a full-stack, high-performance web application designed to replicate the core features of Reddit. It uses a modern, "Dark Cinematic" UI design and is built for speed and scalability.

Originally designed with an in-memory JSON data store and an Express.js backend, the project has been refactored into a **modern Next.js 16 Serverless application** backed by a **Neon PostgreSQL** database, making it fully ready for production deployment on Vercel.

---

## 2. Technology Stack

### Frontend & Core Framework
* **Next.js 16 (App Router):** Handles both the React frontend and the backend API routes via serverless functions.
* **React 18:** Core UI library.
* **TypeScript:** End-to-end type safety.
* **Turbopack:** Ultra-fast local development bundler (`--turbo`).

### UI & Styling
* **Tailwind CSS:** Utility-first CSS framework for styling.
* **Radix UI:** Unstyled, accessible UI primitives (Dialogs, Dropdowns, Avatars, etc.).
* **Framer Motion:** Smooth micro-animations and transitions.
* **Lucide React:** Iconography.

### Database & Data Management
* **Database:** PostgreSQL (Hosted on Neon.tech).
* **Driver:** `pg` (Node Postgres) with connection pooling.
* **Architecture:** The database schema is auto-initialized on the first API hit if it doesn't exist, eliminating the need for external migration tools like Prisma.

---

## 3. Database Schema

The database uses a relational structure designed for performance.

* **`app_users`**: Stores user profiles. 
  * Fields: `id`, `username`, `email`, `password`, `image`, `bio`, `karma`, `is_verified`
* **`app_communities`**: Subreddits/Categories for posts.
  * Fields: `id`, `name`, `description`, `created_at`, `members`, `icon`
* **`app_posts`**: The core content generated by users.
  * Fields: `id`, `title`, `content`, `type`, `url`, `image_url`, `created_at`, `updated_at`, `author_id`, `community_id`
* **`app_comments`**: Nested text discussions attached to posts.
  * Fields: `id`, `post_id`, `content`, `created_at`, `updated_at`, `author_id`
* **`app_votes`**: Tracks upvotes and downvotes.
  * Fields: `user_id`, `post_id`, `type` (`UP` or `DOWN`)
  * *Note: Uses a composite primary key `(user_id, post_id)` to ensure a user can only vote once per post.*
* **`app_sessions`**: Custom JWT/Token-based session management.
  * Fields: `token`, `user_id`

## 4. API Architecture (Next.js Route Handlers)

All API endpoints are located in `frontend/src/app/api/`. They are standard REST APIs built using Next.js Route Handlers (`route.ts`).

### Authentication (`/api/auth`)
* `POST /api/auth/register`: Creates a new user, hashes password (via custom auth logic), and returns a session token.
* `POST /api/auth/login`: Validates credentials and returns a session token.

### Communities (`/api/communities`)
* `GET /api/communities`: Fetches a list of all communities, including post counts.

### Posts (`/api/posts`)
* `GET /api/posts`: Fetches a feed of posts (hydrated with author, community, and vote counts).
* `POST /api/posts`: Creates a new post. Requires Bearer Token.
* `GET /api/posts/[postId]`: Fetches a single post by ID.

### Votes (`/api/vote`)
* `PATCH /api/vote`: Toggles a vote (upvote/downvote/remove) for a specific post by the authenticated user.

### Comments (`/api/comments`)
* `GET /api/comments?postId=...`: Retrieves comments for a specific post.
* `POST /api/comments`: Adds a comment to a post.

## 5. Security & Authentication

The app uses a custom bearer-token session system rather than NextAuth/Auth.js to keep dependencies minimal and logic transparent.

1. When a user logs in, a unique `token` is generated and saved to `app_sessions` in the database.
2. The frontend stores this token (in localStorage/Context).
3. Secure API routes intercept requests, read the `Authorization: Bearer <token>` header, and validate it against the `app_sessions` table to determine the active `user_id`.

## 6. Key Mechanisms & Performance

### Hydration & Caching
The custom `dataStore.ts` implementation includes a `hydratePost` helper. When a post is fetched, this helper concurrently fetches the author, community, vote count, and comment count using `Promise.all`. This ensures that a single API call provides the frontend with all the data it needs to render a rich Post Card without waterfall fetching.

### Turbopack Optimization
The `next.config.js` is optimized for Turbopack (`turbopack: {}`) and uses `optimizePackageImports` for `lucide-react` to ensure blazing fast local compilation speeds, mitigating slow filesystem reads on Windows.

### Seamless Vercel Deployments
Because the app relies on `pg` (which works perfectly in Node.js serverless environments) and auto-initializes its schema on boot, it requires exactly zero manual database migrations. Setting the `DATABASE_URL` in Vercel is the only requirement for a full production deployment.

## 7. Future Expansion Ideas
If you want to continue building on this MVP, consider:
1. **Pagination:** Implementing cursor-based pagination for the `/api/posts` feed to handle thousands of posts.
2. **Nested Comments:** Updating the `app_comments` table with a `parent_id` column to allow replies to comments.
3. **Image Uploads:** Integrating AWS S3 or Uploadthing for actual image hosting instead of URL inputs.
